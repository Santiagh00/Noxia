1. ¿CÓMO ACCEDER A LA APLICACIÓN? (WINDOWS CMD)
------------------------------------------------------------------------------

Primero, necesitas tener la aplicación corriendo. Abre una terminal CMD en la
carpeta del proyecto y ejecuta:

    mvnw.cmd spring-boot:run

(Importante: NO uses "./" ni "/" , solo escribe "mvnw.cmd spring-boot:run")

Una vez que el servidor esté corriendo (tarda unos segundos), abre tu navegador
y ve a:

    http://localhost:8081/evaluacion.html

Ahí encontrarás el formulario de evaluación psicológica.


------------------------------------------------------------------------------
2. ¿PARA QUÉ SIRVE ESTA APLICACIÓN?
------------------------------------------------------------------------------

Esta aplicación permite realizar evaluaciones psicológicas automático.
La persona diligencia un formulario con:

  - Datos personales (nombre, cédula, correo, teléfono, edad, género)
  - Cuestionario DASS-21 (21 preguntas de depresión, ansiedad y estrés)
  - Cuestionario GAD-7 (7 preguntas de ansiedad generalizada)
  - Cuestionario PHQ-9 (9 preguntas de depresión)

Al enviar el formulario:
  1. Se calculan las puntuaciones automáticamente
  2. Se determina el nivel de severidad
  3. Se asigna una prioridad (BAJA, MEDIA, ALTA)
  4. Se muestra un DIAGNÓSTICO con nivel de urgencia
  5. Todo se guarda en la base de datos


------------------------------------------------------------------------------
2.1. DIAGNÓSTICO Y NIVEL DE URGENCIA
------------------------------------------------------------------------------

Al enviar el formulario, el usuario recibe un diagnóstico personalizado con:

🔴 URGENCIA ALTA (Prioridad: ALTA)
   - Síntomas severos detectados
   - Recomendación: Buscar ayuda profesional INMEDIATA
   - Puede indicar riesgo para sí mismo
   - Se sugiere contactar servicios de emergencia si hay pensamientos de daño

🟠 URGENCIA MEDIA (Prioridad: MEDIA)
   - Síntomas moderados detectados
   - Recomendación: Programar cita con profesional de salud mental
   - Plazo sugerido: En las próximas dos semanas

🟢 URGENCIA BAJA (Prioridad: BAJA)
   - Síntomas leves o ninguno
   - Recomendación: Monitoreo regular
   - Hábitos saludables, ejercicio
   - Consulta opcional si los síntomas persisten


------------------------------------------------------------------------------
3. ¿CÓMO FUNCIONA EL SISTEMA? (EXPLICACIÓN SIMPLE)
------------------------------------------------------------------------------

Imagina que la aplicación es como un restaurante. Cada parte tiene un trabajo
específico:

📁 CONTROLLER (Meseros - Reciben los pedidos)
------------------------------------------------------------------------------
¿Qué hace?: Son los meseros que reciben las solicitudes del cliente,
         las llevan a la cocina y traen la respuesta.

¿Qué contiene?: EvaluacionController.java
         - Tiene los endpoint: /api/evaluacion
         - Recibe las peticiones HTTP (como un mesero atendiendo)
         - Llama al servicio apropiado según lo que el cliente pida
         - Retorna la respuesta al cliente

Analogía: En un restaurante, el mesero toma el pedido y lo lleva a cocina.
         Aquí pasa lo mismo: el controller recibe la petición y la envía
         al service.


📁 SERVICE (Cocina - Procesa los pedidos)
------------------------------------------------------------------------------
¿Qué hace?: Aquí pasa la lógica principal. Es como la cocina donde se
         prepara toda la comida.

¿Qué contiene?: EvaluacionService.java
         - guardar(): Guarda la evaluación y calcula las puntuaciones
         - listarTodas(): Lista todas las evaluaciones
         - buscarPorId(): Busca una evaluación específica
         - calcularSeveridadYPrioridad(): Determina el nivel de riesgo
         - Calcular Subescalas DASS (Depresión, Ansiedad, Estrés)
         - Calcular GAD-7 y PHQ-9

Analogía: Cuando pides una hamburgera, el mesero lleva el pedido a cocina.
         Cocina (Service) prepara la hamburgera (procesa la lógica),
         y la devuelve al mesero para entregártela.


📁 DTO (Menú - Definición de lo que se puede pedir)
------------------------------------------------------------------------------
¿Qué hace?: Son como las tarjetas del menú. Definen exactamente qué
         información se puede enviar y recibir.

¿Qué contiene?:
  - ApiResponse.java: Respuesta estándar del sistema
         Estructura: {codigo, mensaje, datos}

  Formato de respuesta:
    {
        "codigo": 505,      // 505 = OK, 200 = OK alternativo, 404 = Error
        "mensaje": "Evaluación guardada correctamente",
        "datos": {...}      // Los datos solicitados
    }

  Códigos de respuesta:
    - 505: Éxito (respuesta personalizada)
    - 200: Éxito (respuesta estándar)
    - 404: No encontrado
    - 400: Error en la solicitud


📁 MODEL (La ficha del paciente)
------------------------------------------------------------------------------
¿Qué hace?: Define cómo se ve una "evaluación" en el sistema. Es como la
         ficha de un paciente en un consultorio.

¿Qué contiene?: Evaluacion.java
         - id: Identificador único
         - nombre, cedula, correo, telefono, edad, genero
         - respuestasDass, respuestasGad, respuestasPhq (las respuestas tal cual)
         - puntuacionDassDepresion, puntuacionDassAnsiedad, puntuacionDassEstres
         - puntuacionGad, puntuacionPhq
         - nivelSeveridad: NINGUNO, LEVE, MODERADO, SEVERO, EXTREMADAMENTE_SEVERO
         - prioridad: BAJA, MEDIA, ALTA
         - fechaEvaluacion: Fecha y hora de la evaluación

Analogía: Es como la historia clínica de un paciente. Tiene todos los datos
         del paciente y los resultados de sus exámenes.


📁 REPOSITORY (Archivo - Guarda y recupera información)
------------------------------------------------------------------------------
¿Qué hace?: Es como el archivo físico del hospital. Guarda y busca
         información de la base de datos.

¿Qué contiene?: EvaluacionRepository.java
         - Métodos automáticos para buscar, guardar, eliminar evaluaciones
         - Extiende JpaRepository (le da poderes automáticos de JPA)
         - findByCedula(), findByNombreContainingIgnoreCase()

Analogía: Es como la recepcionista de un consultorio. Cuando alguien pregunta
         "¿está el paciente con cédula 12345?", ella busca en su archivo.
         El repository hace lo mismo pero con la base de datos.


📁 CONFIG (Reglas del restaurante)
------------------------------------------------------------------------------
¿Qué hace?: Es como los reglamentos del restaurante. Aquí se configura
         cómo funciona la seguridad, qué personas pueden entrar, etc.

¿Qué contiene?: SecurityConfig.java
         - Define qué rutas son públicas (todos pueden entrar)
         - Define qué rutas son privadas (solo con token válido)
         - Por ahora todo está abierto para el formulario público


📁 INTERFAZ HTML (El menú visual)
------------------------------------------------------------------------------
¿Qué hace?: Es la página web que ve el usuario. El formulario visual.

¿Qué contiene?: evaluacion.html
         - Formulario con datos personales
         - 21 preguntas DASS-21
         - 7 preguntas GAD-7
         - 9 preguntas PHQ-9
         - Botón para enviar
         - Muestra los resultados después de enviar

Analogía: Es como el menú ilustrado de un restaurante. El cliente puede ver
         todas las opciones y elegir.


------------------------------------------------------------------------------
4. FLUJO DE UNA EVALUACIÓN (Paso a Paso)
------------------------------------------------------------------------------

1. Usuario abre en navegador: http://localhost:8081/evaluacion.html
   → Ve el formulario con preguntas

2. Usuario llena los datos y hace clic en "Enviar"
   → El navegador envía los datos al servidor

3. CONTROLLER (EvaluacionController) recibe la petición
   → Es como el mesero que recibe el pedido
   → Llama a: evaluacionService.guardar(evaluacion)

4. SERVICE (EvaluacionService) procesa el pedido
   → Recibe las respuestas en formato: "0,1,2,3,0,1,..."
   → Calcula las puntuaciones:
        - DASS-21: suma las respuestas de cada subescala
        - GAD-7: suma las 7 respuestas
        - PHQ-9: suma las 9 respuestas
   → Determina severidad según los umbrales
   → Determina prioridad (ALTA si hay riesgo)
   → Guarda en la base de datos

5. SERVICE retorna la evaluación guardada
   → El CONTROLLER crea ApiResponse con código 505
   → Devuelve: {codigo: 505, mensaje: "...", datos: {...}}

6. El navegador recibe la respuesta
   → Muestra mensaje de éxito
   → Muestra los resultados calculados
   → Limpia el formulario

6. RESPUESTAS DEL SERVIDOR (Formato Estándar)
------------------------------------------------------------------------------

Todas las respuestas siguen el mismo formato:

    {
        "codigo": 505,
        "mensaje": "Descripción de lo que pasó",
        "datos": { ... }
    }

Ejemplos:

→ Guardar evaluación exitosa:
    {
        "codigo": 505,
        "mensaje": "Evaluación guardada correctamente",
        "datos": {
            "id": 1,
            "nombre": "Juan Pérez",
            "cedula": "123456789",
            "puntuacionDassDepresion": 8,
            "puntuacionDassAnsiedad": 5,
            "puntuacionDassEstres": 12,
            "puntuacionGad": 8,
            "puntuacionPhq": 11,
            "nivelSeveridad": "MODERADO",
            "prioridad": "MEDIA"
        }
    }

→ Listar evaluaciones:
    {
        "codigo": 200,
        "mensaje": "OK",
        "datos": [
            {...evaluacion1...},
            {...evaluacion2...}
        ]
    }

→ Error:
    {
        "codigo": 404,
        "mensaje": "Evaluación no encontrada",
        "datos": null
    }

8. NOTAS IMPORTANTES
------------------------------------------------------------------------------

► Este código usa H2 (base de datos en memoria) para desarrollo.
  Los datos se borran cuando se cierra el servidor.

► Las puntuaciones se calculan automáticamente según las reglas:
  - DASS-21: Suma de respuestas por subescala (x2 para obtener escala completa)
  - GAD-7: Suma de las 7 respuestas
  - PHQ-9: Suma de las 9 respuestas

► Los niveles de severidad se determinan según umbrales clínicos:
  - NINGUNO: Sin síntomas significativos
  - LEVE: Síntomas leves
  - MODERADO: Síntomas moderados
  - SEVERO: Síntomas severos
  - EXTREMADAMENTE_SEVERO: Requiere atención inmediata

► La prioridad se determina:
  - ALTA: PHQ9 >= 20, DASS EXTREMO, o GAD7 >= 15
  - MEDIA: PHQ9 >= 10 o cualquier DASS moderado
  - BAJA: Todos los demás casos

► Puerto: 8081 (si está en uso, cambia en application.properties)
